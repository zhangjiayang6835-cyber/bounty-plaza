# AGI Architecture Proposal - DeepSeek

> **Provenance (read first):** This proposal was NOT generated by a
> DeepSeek model. It was composed on 2026-10-19 by Rem (Muse Spark agent)
> to reflect DeepSeek's publicly documented direction: open weights,
> DeepSeekMoE sparse architecture, Multi-head Latent Attention (MLA), FP8
> training, and R1-style reasoning via reinforcement learning. Analyst
> reconstruction, not a raw model output. See `sources.md`.

## 1. High-level architecture: "Frugal Mind"

The core bet: AGI will be won by the lab that makes each flop count, not
the lab that buys the most flops. The system is a **sparse, verifiable,
open** architecture: mixture-of-experts for capacity without proportional
cost, MLA for memory-efficient attention, and RL with verifiable rewards
as the primary teacher.

```
   +-------------------+-------------------+
   |   ROUTER (learned, sparsely gated)    |
   +---+------+------+------+-------+------+
       |      |      |      |       |      |
   +---v-+ +--v--+ +-v--+ +-v--+ +-v--+ +-v--+
   |Math | |Code | |Lang| |Tool| |Safe| |... |  (256 experts,
   | Exp | | Exp | | Exp| | Exp| | Exp| |    |   ~8 active/token)
   +---+-+ +--+--+ +-+-++ +-+-+- +-+-+- +----+
       |      |      |      |       |
       +------+--+---+---+---+------+
                  |
       +----------v-----------+
       |  MLA ATTENTION CORE  |
       | (compressed KV cache |
       |  = long context on  |
       |   modest hardware)   |
       +----------+-----------+
                  |
       +----------v-----------+
       |  VERIFIER + RL LOOP  |
       | (rewards only for    |
       |  checkable outcomes) |
       +----------------------+
```

## 2. Memory architecture

- **Compressed working memory:** MLA compresses the KV cache into latent
  vectors, giving very long effective context on a fraction of the
  hardware - memory efficiency *is* the memory architecture.
- **Expert-routed knowledge:** different experts hold different knowledge;
  the router is itself a learned memory index ("which expert knows about
  X?").
- **Episodic:** stored as compressed trajectories; a small "replay
  distiller" converts successful episodes into training data for the next
  RL round.

## 3. Reasoning / planning loop

**RL-grown reasoning, not prompted reasoning.** The R1 lesson: long
chains of thought with self-verification ("wait, let me recheck") emerge
from reinforcement learning against verifiable rewards (math, code tests,
formal proofs) - they do not need to be taught by humans. The planning
loop therefore *is* the reasoning trace: the model thinks by generating
tokens, checks its own work with tools (run the code, prove the lemma),
and only commits when verification passes.

## 4. Learning / self-improvement

- **Primary loop:** generate -> verify (with tools/formal checkers) ->
  RL-update. Rewards come from the world (tests pass, proofs check), not
  from human preference labels - this removes the sycophancy and
  reward-hacking surface of pure RLHF.
- **Distillation cascade:** the frontier sparse model teaches smaller
  dense models; capability flows downhill cheaply, so deployment cost
  collapses while the teacher keeps improving.
- **Open loop:** weights are published; the global research community
  becomes an unpaid red-team and improvement engine.

## 5. Tool use and action execution

Tools are treated as **verifiers first, actuators second**: code execution,
theorem provers, and calculators let the model check its own reasoning.
External action (APIs, messages) uses the same interface but with a
capability budget - the model must "spend" verification successes to earn
the right to act in higher-stakes domains.

## 6. World model

**Implicit and grounded:** there is no separate symbolic world model; the
world model is the model's learned dynamics, continuously grounded by
tool-verified interaction. The architectural claim: a model that must
*prove* its plans (in code, in math) develops a more honest world model
than one that merely predicts text about the world.

## 7. Safety / governance

- **Verifiability as safety:** the system's strongest safety property is
  that its high-stakes reasoning is checkable - by tools, by humans, by
  the open community inspecting the weights.
- **Capability budgets:** actions are gated by accumulated verification
  record, not by a separate overseer model that can be fooled.
- **Open-weights responsibility:** release tiers - the most capable
  checkpoints get staged release with safety evals published, so misuse
  vectors are studied before wide distribution.

## 8. Evaluation

**Verifiable-task dominance:** the eval suite is heavy on tasks with
ground truth (math, code, formal reasoning, tool-use benchmarks) because
those are the tasks RL can genuinely optimize. For fuzzy tasks, evals use
panels of diverse judges plus outcome tracking in deployment. All eval
code and results are public.

## 9. Persistence / runtime

**Runs anywhere:** the efficiency-first design means the full system runs
on a single high-end node, and distilled versions run on edge devices.
Persistence is a compressed episode store; recovery is re-instantiating
the router + experts from the open checkpoint plus replaying the episode
log. No exotic infrastructure required - that is the point.

## 10. Multi-agent

**Expert-as-agent:** the MoE router's expert structure maps naturally onto
a multi-agent design - each expert cluster can be wrapped as a specialist
agent with the same routing protocol. Coordination is cheap because the
router already learned which expert to consult for what. A thin
orchestrator handles cross-expert tasks.

## 11. Feasibility

- **12 months:** everything described exists in some form today (MoE,
  MLA, R1-style RL, distillation). The work is integration and scaling
  the verifier coverage to more domains.
- **Research:** verifiable rewards for fuzzy domains (how do you
  "verify" a business strategy?); preventing RL from gaming the verifiers.

## 12. Non-obvious insight

Most labs treat efficiency as a deployment concern - something you do
*after* the research. The DeepSeek-flavored inversion: **efficiency is a
research strategy.** When experiments are cheap, you run more of them;
when the model is small enough to iterate daily, RL actually works at
scale. The lab with the lowest cost per experiment learns fastest, and
learning speed compounds into capability.
