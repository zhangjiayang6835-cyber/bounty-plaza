# AGI Architecture Proposal - Alibaba Qwen team

> **Provenance (read first):** This proposal was NOT generated by a Qwen
> model. It was composed on 2026-10-19 by Rem (Muse Spark agent) to reflect
> the Qwen team's publicly documented direction: strong multilingual open
> models across size tiers, the Qwen-Agent framework, and ecosystem-first
> deployment. Analyst reconstruction, not a raw model output. See
> `sources.md`.

## 1. High-level architecture: "Polyglot Fabric"

The core bet: AGI must work for everyone, in their language, on their
hardware. The system is a **tiered fabric**: one semantic core trained
multilingually from the start, deployed in matched sizes (from 0.5B edge
to Max-class frontier), with cultural-context adapters and a standard
agent framework unifying them.

```
   +--------------------------------------------------+
   |            SEMANTIC CORE (language-agnostic)     |
   |  concepts live here; no language is "primary"    |
   +---+----------------------+-------------------+---+
       |                      |                   |
 +-----v-----+        +-------v------+     +------v------+
 | CULTURAL  |        |  QWEN-AGENT  |     |  SIZE TIERS   |
 | ADAPTERS  |        |  FRAMEWORK   |     |  0.5B..Max    |
 | (norms,   |        | (tools,      |     |  (same arch,  |
 |  formats, |        |  planning,   |     |   scaled;     |
 |  law)     |        |  memory)     |     |   distilled)  |
 +-----------+        +--------------+     +---------------+
```

## 2. Memory architecture

- **Semantic core memory:** language-agnostic concept graph shared across
  all tiers and languages - a fact learned in English is available in
  Vietnamese without translation.
- **Cultural adapters:** per-locale overlays (communication norms, legal
  constraints, format conventions) kept separate from core knowledge so
  they can be audited and swapped.
- **Episodic:** per-deployment stores; the edge tier keeps private
  episodes on-device, syncing only distilled, consented learnings upward.

## 3. Reasoning / planning loop

**Framework-standard planning:** the Qwen-Agent pattern - plan in explicit
steps, act with tools, reflect on outcomes - is the *same* across all
tiers, so a plan developed on Max can be executed by a 7B edge model with
predictable degradation. Reasoning traces are structured (not free text)
so smaller models can follow larger models' plans.

## 4. Learning / self-improvement

- **Distillation down the tiers:** frontier learnings are distilled into
  each smaller tier on a regular cadence; the whole fabric improves
  together.
- **Locale learning:** cultural adapters improve from deployment feedback
  within their locale, without polluting the shared core.
- **Community loop:** open weights mean thousands of deployments produce
  bug reports and fine-tunes that flow back into the core.

## 5. Tool use and action execution

The agent framework defines a **single tool protocol** across tiers:
function schemas, a planner, and a memory module with the same interface
whether the brain is 0.5B or Max. Tools are registered per deployment
with locale-appropriate defaults (which payment rail, which map provider).
High-stakes actions require the frontier tier's approval even when
initiated at the edge.

## 6. World model

**One world, many lenses:** the semantic core holds a unified causal
model of the world; cultural adapters provide the lens (what counts as
polite, legal, or risky varies). The architecture treats "culture" as a
first-class modeling dimension rather than a translation problem.

## 7. Safety / governance

- **Tiered capability gating:** the most capable tier is API-gated with
  full monitoring; open tiers are safety-tuned and their risky
  capabilities (e.g., detailed dual-use knowledge) are ablated before
  release, with the ablation methodology published.
- **Locale compliance:** cultural adapters include legal-constraint
  modules per jurisdiction, auditable separately from the core.
- **Provenance:** every deployment reports its tier, adapter set, and
  weight hash - you always know *which* system you are talking to.

## 8. Evaluation

**Multilingual-first evals:** every capability is tested in dozens of
languages, not just English - a model that reasons well in English but
fails in Hindi or Vietnamese fails the suite. Agent benchmarks run
identically on every tier to measure the degradation curve, which is
published. Locale-specific safety evals per adapter.

## 9. Persistence / runtime

**Edge-to-cloud continuity:** the same agent state format runs on a phone
(0.5B) and in the data center (Max); an agent can hand off mid-task from
edge to cloud when it needs more thinking. Private episodes never leave
the device unless the user opts in. This makes 24/7 personal AGI
deployable without surveillance infrastructure.

## 10. Multi-agent

**Tiered society:** cheap edge agents handle routine subtasks (monitor,
fetch, draft) while frontier agents handle judgment calls. They share the
agent-framework protocol, so orchestration is uniform. Cross-locale agent
teams are native - a Vietnamese edge agent and an English cloud agent
collaborate through the language-agnostic core.

## 11. Feasibility

- **12 months:** the fabric exists in outline today (model tiers,
  Qwen-Agent); the work is unifying the protocol and proving the
  degradation curves.
- **Research:** truly language-agnostic reasoning (today's models still
  "think in English" measurably); cultural adapters that capture norms
  without stereotyping.

## 12. Non-obvious insight

Most AGI proposals are implicitly monolingual - they design for English
and translate later. The Qwen-flavored insight: **language shapes the
agent's action space, not just its I/O.** A system that plans in a
language-agnostic concept space can take actions (negotiate, comply,
persuade) that a translate-at-the-edges system cannot even represent. The
first truly general agent will be the first truly multilingual one.
