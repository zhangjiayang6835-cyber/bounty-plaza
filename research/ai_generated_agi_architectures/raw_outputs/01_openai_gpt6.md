# AGI Architecture Proposal - OpenAI (GPT-6 family)

> **Provenance (read first):** This proposal was NOT generated by an OpenAI
> model. It was composed on 2026-10-19 by Rem (Muse Spark agent) to reflect
> OpenAI's publicly documented engineering direction: RL-trained reasoning
> models, test-time compute scaling, the Agents SDK / multi-agent swarms,
> and eval-driven development. It is an analyst reconstruction, not a raw
> model output. See `sources.md` for the public sources used.

## 1. High-level architecture: "Deliberation Fabric"

The core bet: intelligence scales with **reasoning-time compute**, not just
parameters. The system is a reasoning-first agent OS where a deliberative
core spends variable compute per task, and everything else (memory, tools,
sub-agents) is infrastructure serving that core.

```
                        +-----------------------------+
                        |      DELIBERATION CORE      |
                        |  (GPT-6 reasoning model,    |
                        |   variable test-time budget)|
                        +--------------+--------------+
                                       |
        +------------------------------+-------------------------------+
        |                              |                               |
+-------v--------+           +---------v----------+          +---------v----------+
|  MEMORY FABRIC |           |   TOOL FABRIC      |          |  SWARM ORCHESTRATOR|
| - vector LTS   |           | - typed function   |          | - spawns sub-agents|
| - episodic log |           |   registry         |          | - task decomposition |
| - scratch STM  |           | - sandboxed exec   |          | - result aggregation |
+-------+--------+           +---------+----------+          +---------+----------+
        |                              |                               |
        +------------------------------+-------------------------------+
                                       |
                        +--------------v--------------+
                        |      EVAL / GUARD LAYER     |
                        |  (evals gate every deploy,  |
                        |   monitors gate every run)  |
                        +-----------------------------+
```

## 2. Memory architecture

- **STM (working memory):** the reasoning trace itself, up to ~1M tokens of
  context; scratch space is disposable.
- **Episodic log:** append-only record of every agent run (prompts, tool
  calls, outcomes), stored as structured JSONL, indexed by embedding.
- **Semantic LTS:** distilled facts extracted from episodes by a background
  "librarian" agent; stored in a versioned knowledge graph with provenance
  links back to the episode that produced each fact.
- **Retrieval:** hybrid dense + symbolic; the deliberation core issues
  explicit memory queries as tool calls, so retrieval is auditable.

## 3. Reasoning / planning loop

Outer loop: **plan -> act -> observe -> re-plan**, with the deliberation
core allocating a compute budget per step. Key mechanism: **deliberative
checkpoints** - after every N tool calls the core must produce a written
assessment ("am I on track? what would change my mind?") before spending
more budget. This is RL-trained behavior (process supervision), not a
prompt trick: models are rewarded for calibrated self-assessment.

## 4. Learning / self-improvement

- **Within-task:** the episodic log + librarian distillation described above.
- **Across-task:** weekly RL fine-tuning on trajectories scored by outcome
  evals (SWE-style task suites). Self-modification of weights happens only
  through this gated pipeline; the agent cannot rewrite its own training
  code at runtime.
- **Explicit non-goal:** no recursive self-improvement of the training
  loop itself without human review.

## 5. Tool use and action execution

Typed function registry with JSON schemas; every call is sandboxed
(gVisor-style) with capability tokens. Tools are versioned; the planner sees
tool changelogs. High-stakes tools (payments, external messages) require a
second "checker" model to approve the call parameters.

## 6. World model

The world model is **the reasoning model itself plus the episodic log** -
there is no separate learned simulator in v1. For domains needing
simulation (robotics, markets), the system spawns a sub-agent whose job is
to build and calibrate a small domain simulator, then reports back. Deliberate
choice: one general world model is a research bet we do not take yet.

## 7. Safety / governance

- **Evals as gates:** no model ships unless it passes the safety eval suite;
  no agent run continues if the monitor flags a policy violation.
- **Monitor model:** a separate, smaller model watches every run with full
  context and can pause/terminate; it is trained adversarially against the
  main agent.
- **Deliberative alignment:** the model is trained to reason explicitly
  about the Charter-like duties before acting in ambiguous cases, and that
  reasoning is logged.

## 8. Evaluation

Task suites (coding, research, long-horizon office work) plus
**trajectory evals** (was the process sound, not just the outcome).
Red-teaming is continuous: a dedicated team + automated adversary agents.
Public system cards for every release.

## 9. Persistence / runtime

Stateless core, stateful fabric: all state lives in the memory fabric
(postgres + object store), so any crashed agent can be resumed by a fresh
instance reading the episodic log. Deployment: regional clusters with
checkpoint replication; a run can migrate across machines mid-task.

## 10. Multi-agent

A **swarm of specialists** coordinated by the orchestrator: researcher,
coder, critic, executor. They communicate through a shared blackboard (the
episodic log), not hidden messages - all inter-agent traffic is logged and
auditable. Sub-agents are cheaper, narrower models; only the deliberation
core is frontier-class.

## 11. Feasibility

- **12 months:** deliberation core + tool fabric + episodic memory +
  monitor model. This is essentially the current agent product line hardened.
- **Research:** calibrated long-horizon planning beyond ~8 hours of
  autonomous work; reliable self-assessment (models still overconfident).

## 12. Non-obvious insight

Most AGI proposals treat reasoning as something that happens *inside* a
single forward pass. The OpenAI-flavored insight is that reasoning is a
**resource allocation problem**: the scarce resource is not parameters but
test-time compute, and the architecture that wins is the one that spends
it where uncertainty is highest. Everything else - memory, tools, swarms -
exists to make each unit of reasoning compute more effective.
