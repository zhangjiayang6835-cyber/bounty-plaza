# AGI Architecture Proposal - Google DeepMind (Gemini family)

> **Provenance (read first):** This proposal was NOT generated by a Google
> model. It was composed on 2026-10-19 by Rem (Muse Spark agent) to reflect
> Google DeepMind's publicly documented direction: natively multimodal
> training, million-token context, Project Astra (universal agent), and
> AlphaEvolve-style self-improving systems. Analyst reconstruction, not a
> raw model output. See `sources.md`.

## 1. High-level architecture: "Omni-Substrate"

The core bet: the world is multimodal, so the substrate must be too - from
the first training step, not bolted on. One natively multimodal
transformer ingests text, vision, audio, video, and sensor streams into a
single representation space, and a **world simulator** grown inside that
space lets the agent rehearse actions before taking them.


## 2. Memory architecture

- **Working memory:** the million-token context window *is* the working
  memory - entire projects, codebases, and video histories stay resident.
- **Episodic:** multimodal episode store (what was seen/heard/done),
  indexed by the same encoders, so you can query "show me when the robot
  last saw this part."
- **Semantic:** distilled into the model's weights through periodic
  continual pre-training on curated episode data, plus a structured
  knowledge store for facts needing exact recall.
- Key property: memory is **modality-agnostic** - a memory can be stored as
  video and retrieved by a text query.

## 3. Reasoning / planning loop

**Simulate-then-act.** For any non-trivial plan, the world simulator rolls
out candidate trajectories (as imagined multimodal sequences), scores them
against the goal and safety constraints, and only then executes the best
one in reality. Planning is literally "dreaming in the same representation
as perceiving," which is why native multimodality matters: there is no
translation loss between perception and imagination.

## 4. Learning / self-improvement

- **AlphaEvolve pattern:** the system proposes improvements to its own
  components (prompts, tools, even simulator code), tests them against
  evals, and keeps what wins - an evolutionary loop with humans setting the
  fitness function.
- **Continual learning:** periodic retraining on curated multimodal
  episodes; elastic weight consolidation to avoid forgetting.
- **Guardrail:** the evolution loop cannot change the safety shell or the
  eval suite that judges it.

## 5. Tool use and action execution

The action fabric spans **digital and physical**: APIs and code execution
on one side, robotics control on the other, addressed through the same
interface. The simulator rehearses physical actions before the robot moves.
Tool outputs return as multimodal observations (screenshots, sensor traces),
closing the loop in the native representation.

## 6. World model

The world simulator is the centerpiece: a generative model of "what
happens next" conditioned on state + action, trained on video, robotics,
and interaction data. It is explicitly **calibrated** - it reports its own
uncertainty, and the planner treats high-uncertainty simulations as a
reason to gather real information first.

## 7. Safety / governance

- **Rehearsal as safety:** dangerous plans fail in simulation first.
- **Multimodal oversight:** safety classifiers operate on the same
  multimodal stream (they can *see* what the agent sees).
- **Tiered deployment:** on-device models handle private data locally;
  only explicitly authorized subtasks go to the cloud - privacy by
  architecture.
- **Frontier safety framework:** capability thresholds trigger reviews
  before training and deployment.

## 8. Evaluation

Simulation-based evals (thousands of rehearsed scenarios per release) plus
real-world task suites. **Counterfactual evals:** "would the system have
acted safely if the observation had been adversarial?" - tested by
perturbing simulator inputs. Multimodal red-teaming (adversarial images,
audio) is standard.

## 9. Persistence / runtime

**Cloud-edge continuum:** a small on-device model maintains continuity
(remembers you, handles private context) while the frontier model handles
heavy reasoning in the cloud; state syncs through the episodic store.
Long-running agents checkpoint simulator state, so a week-long project
survives restarts.

## 10. Multi-agent

**Specialist ensemble with a shared world model.** Multiple agents (coder,
researcher, operator) share one simulator, so they literally imagine the
same world - coordination failures from divergent world models disappear.
A coordinator agent allocates simulation budget between agents.

## 11. Feasibility

- **12 months:** omni core + action fabric for digital tasks + rehearsal
  for short-horizon plans. (This is the Astra trajectory.)
- **Research:** a simulator reliable enough for long-horizon physical
  tasks; calibrated uncertainty that survives distribution shift.

## 12. Non-obvious insight

Most proposals separate "thinking" from "perceiving." The DeepMind-flavored
insight: **the representation you perceive in should be the representation
you plan in.** Every translation between modalities (vision -> text ->
plan -> action) loses information and adds failure modes. Native
multimodality is not a feature - it is the removal of a dozen translation
layers where AGI plans go to die.
