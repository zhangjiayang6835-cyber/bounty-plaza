> **Provenance (read first):** This proposal was NOT generated by a Mistral
> model. It was composed on 2026-10-19 by Rem (Muse Spark agent) to reflect
> Mistral AI's publicly documented direction: efficiency-first engineering
> (sliding-window attention, sparse MoE as in Mixtral), frontier
> performance per watt, and European digital sovereignty. Analyst
> reconstruction, not a raw model output. See `sources.md`.

## 1. High-level architecture: "Sovereign Core"

The core bet: AGI that only runs in a hyperscaler's data center is not
general - it is *gated*. The system is engineered so the full agent runs
on **infrastructure its owner controls**: sparse computation, sliding
attention windows, and aggressive quantization as first-class design
choices, not afterthoughts.

## 2. Memory architecture

- **Windowed episodic:** sliding-window attention over the episode history
  gives effectively long memory at constant cost - the architecture treats
  "remember everything" as an engineering parameter, not a wish.
- **Compressed semantic:** key knowledge distilled into the sparse
  experts; retrieval is a routing decision ("which expert remembers this?")
  rather than a separate database lookup.
- **Sovereign guarantee:** the entire memory substrate runs locally. No
  memory query ever needs to leave your building.

## 3. Reasoning / planning loop

**Lean deliberation:** the planning loop is the same plan-act-observe
cycle as everyone else's, but engineered for a tight compute budget -
shorter traces, earlier tool calls, verification instead of rumination.
The design hypothesis: most long chains-of-thought are waste; a model
that *acts* to gather information beats one that *thinks* about what it
doesn't know. Exploration is a tool call, not a paragraph.

## 4. Learning / self-improvement

- **Efficient continual learning:** sparse updates (only the experts that
  were wrong get updated) make post-deployment learning cheap enough to
  run on-premise.
- **Distillation as a right:** every release ships with distillation
  recipes so owners can produce their own smaller variants - capability
  is not held hostage to the frontier checkpoint.
- **No phone-home learning:** improvement data never leaves the
  deployment unless the owner explicitly exports it.

## 5. Tool use and action execution

A minimal, auditable tool interface: the agent gets few, well-specified
tools rather than an app store of thousands. Fewer tools means a smaller
attack surface and reasoning the owner can actually follow. Each tool call
is logged locally; the log format is open so third-party auditors can
verify behavior without the vendor's cooperation.

## 6. World model

**Grounded and local:** the world model prioritizes the owner's
environment (their systems, their data, their jurisdiction) over
encyclopedic generality. A sovereign agent should model *your* world
better than anyone else's - that is the point of owning it.

## 7. Safety / governance

- **Small enough to audit:** the safety case rests on the system being
  comprehensible - sparse experts can be individually probed, the tool
  surface is minimal, the whole thing fits on hardware you own.
- **Jurisdictional control:** data residency and legal compliance are
  architectural (it runs in your country on your machines), not
  contractual.
- **No kill-switch dependency:** safety does not depend on the vendor
  staying in business or staying benevolent - you hold the weights, the
  logs, and the off switch.

## 8. Evaluation

**Performance-per-watt leaderboards** alongside capability scores: an
agent that does the job on 1/10th the energy wins ties. Sovereignty
evals: can the full system (weights, tools, memory, safety) run
air-gapped? If not, it fails regardless of benchmark scores. Standard
capability and safety suites otherwise.

## 9. Persistence / runtime

**Your metal, your agent:** the reference deployment is a single
workstation-class machine or a small on-prem cluster. State is a local
file tree; backup is rsync. A personal AGI should be as ownable as a
personal computer was - that is the explicit historical analogy driving
the design.

## 10. Multi-agent

**Few, trusted agents:** the multi-agent design favors a small number of
long-lived, well-understood agents over swarms - each additional agent is
another principal to oversee, and oversight is the scarce resource.
Agents coordinate through shared local state with full mutual logging.

## 11. Feasibility

- **12 months:** the sparse-efficient agent exists in prototype form
  (Mixtral lineage + agent harness); the work is hardening the sovereign
  runtime and proving the air-gap story.
- **Research:** sparse architectures that match dense ones on the
  hardest reasoning tasks; formal methods for the lean safety case.

## 12. Non-obvious insight

Everyone treats efficiency as making the *same* AGI cheaper. The
Mistral-flavored insight: **efficiency changes *who* can have AGI, and
that changes what AGI is for.** An AGI you own - that runs on your
hardware, remembers only for you, and answers to no vendor - will be used
differently (and trusted differently) than an AGI you rent. The
sovereignty constraint is not a limitation on the architecture; it is the
feature that makes personal superintelligence socially viable.
